## 本轮目标

## 关键发现：三个真实输入层 Bug（已修）
之前所有 VM 测试都绕过了 `ui.js` 的键盘处理，所以这三个 bug 一直没被发现。
用 Chrome DevTools Protocol 派发**真实**鼠标/键盘事件后才暴露：

1. **`C`（蹲下）与 `B`（破墙）完全失效**
   - 原因：`ui.js` 里 `if (['A','B','C','D'].includes(k)) { executeGo(); return; }` 排在最前面，
     把后面的 `if (k === 'C') { 蹲 }` / `if (k === 'B') { 破墙 }` 全部挡死。
   - 修法：GO Code 只保留数字键 `1-4`（`sim.goCodes[idx]` 本来就映射到 A/B/C/D 组），
     删掉 A-D 分支，把 C / B 还给单键操作。
2. **`Esc` 无效**
   - 两层原因：① `e.key` 对 Esc 返回 `'Escape'`，代码判的是 `k === 'ESC'`，永远不匹配；
     ② `UI.togglePauseMenu` 只处理 `live`/`paused`，而开局是 `planning`，所以即使键名对了也没反应。
   - 修法：键名判 `'ESCAPE' || 'ESC'`；并把 `togglePauseMenu` 改成**取消优先**语义
     （先关帮助面板 → 再取消当前工具 → 最后才切换暂停）。
3. **文档与实现不符（`TAB` 多选）**
   - 帮助表写了 `TAB = 多选队员`，但键盘处理里没有 TAB 分支。
   - 修法：**实现**它（循环加入下一个未选中队员，全选完回到第一个），而不是删文档。

## 第二轮：右键拖拽调朝向 + 战术信条技能树

### 需求
「添加右键队员后拖拽跟随鼠标调整角度，以及技能树系统，技能树参考 DoorKickers 一代」

### 调研结论（DK1 的 Doctrine）
用 multi-search-engine 查到的关键事实，直接影响设计：
- DK1 技能树叫 **Doctrine（战术信条）**，**按武器类别分三棵树**（手枪 / 长枪 / 霰弹枪），
  **不按职业分**；效果对**全队所有队员**生效，不是单个队员养成。
- 点数来自**小队等级**，每级 1 点，**等级上限 21**。
- 节点有前置节点，部分节点额外要求「该树已投入 N 点」。
- **重置无成本**。
- 具体节点名：Point Shooting / Surgical Shooting / Quick Draw / Double Tap / Long Range Drills /
  Mozambique / Center Axis Relock；Close Range Engagements / Medium Range Drills / Barricade Shooting /
  Transition / Back Breaker / Negate Cover / Go Silent；Recoil Control / Fast Pump /
  Ejection Port Reload / One Shot Breach。

### 本项目的落地（js/doctrine.js）
三棵树按 `DATA.WEAPONS[..].cls` 分：pistol / longgun（assault+smg+marksman+lmg+grenadier）/ breach。
20 个节点，XP_PER_LEVEL=200，上限 21 级。XP = 胜利 120 + 每星 40，失败保底 40，重复通关 30%。

### 🚨 发现的真 bug
1. **破门耗时从未生效**：`DATA.BREACH` 里每种方式都有 `time`（踹门 1150ms、撬棍 4200ms…），
   但代码一律传 `dur: 100` —— 等于瞬间破门，破门菜单上显示的「耗时 1.2s」是假的。
   改成 `ENG.breachDur()` 统一取基础值 × 信条倍率。破门树节点这才有意义。
2. **`docMerge` 的乘法判定写错**：用 `k.slice(-3) === 'Mul'` 判断乘法，
   但 `aimMulNear` / `aimMulFar` 的 `Mul` 在中间 → 误走加法分支（0.8 变成 1.8）。
   改成 `k.indexOf('Mul') >= 0`。**是 doctest 抓出来的。**
3. **模块漏了 `window.X = X` 导出**：本项目约定每个模块末尾显式挂到 window
   （`window.SIM = SIM` 等，在 mapgen/engine/ai/sim/main 里都有）。
   doctrine.js 我漏了 → VM 沙箱里 `sandbox.DOCTRINE` 是 undefined，
   但 `vm.runInContext('DOCTRINE', ctx)` 能取到（顶层 const 进的是全局词法环境，不是全局对象属性）。
   排查手法：先写探针打印 `typeof sandbox.X` vs `runInContext('typeof X')` 对照。

### ⚠️ 差点误判的"平衡回归"（重要教训）
接对破门耗时后，realplay 从 12/12 掉到 11/12。**差点就去改关卡平衡。**
做了两步隔离实验才看清真相：
- 加了 `DK2D_INSTANT_BREACH=1` 开关把破门还原成瞬间 → 12/12。
- 又加了 `DK2D_SEED_OFFSET` 平移种子，多组对比：
  **真实破门 11/11/11，瞬间破门 12/10/10** —— 原来那个 12/12 只是**单条随机种子运气好**。
  本游戏所有随机走同一条种子序列，改任何时序都会整体改变随机轨迹。
- 结论：不是系统性变难，保留改动。
**教训：单次跑出来的通关率不能当结论，必须换种子看分布。**

### 右键拖拽调朝向
- 用上了 `ui.js` 里**声明了但从未使用**的 `focusDrag` 变量（`tempFace` 同样是只写不读的死标记）。
- 关键坑：拖拽时只设 `lookX/lookY` 是不够的 —— **规划态（暂停）下 `updateTrooper` 不执行**，
  视野锥会纹丝不动。必须直接 `t.face = ang` 做 1:1 跟手。
- 顺手让「临时朝向 / Ctrl 强制 / Shift 锁定」三种文档里写的行为**真的都成立**
  （原来 `tempFace` 没实现，三者其实等价）。临时朝向 = 一移动就恢复沿路径朝向。
- 窗口 `blur` 时清拖拽状态，防止松手事件丢在窗口外导致视野锥粘住鼠标。

## 第三轮：敌人受击反应

### 需求
「NPC 即使是被击中也不反击，而是等待听到声音或视野范围内，改为被击中后转向被击中方向」

### 根因
`ENG.damage` 本来就会写 `target.attackSource`，但**敌人 AI 完全没读这个字段**：
- 敌人的感知只走 `updatePerception`（视野锥 + 视线）；
- 状态切换只认 `visibleTarget` 和 `makeNoise` 的声音事件。
所以从背后挨枪 → 视野锥扫不到射手 → 一直站着被打死。
（玩家队员在 `player.js` 里是有受击转向的，敌人没有。）

### 连带发现的 bug
`hurtT`（受击白闪计时器，`ENG.damage` 里设 260）**只在 `player.js` 的玩家分支里递减**，
敌人挨一枪后 `hurtT` 永远是 260。而 `render.js` 拿 `hurtT / 260` 当白闪强度 →
**敌人被打中一次就会永久发白**。已把递减统一到 `ENG.updateUnit` 的计时器区。

### 实现
`js/engine.js`：
1. `ENG.damage` 增加 `turnToSourceT = 900`（转向时间窗，比 260ms 的白闪长，够转半圈）
   和 `hurtStamp++`（每次受击的唯一序号）；并兜底用 `from` 写 `attackSource`，
   这样爆炸/近战等路径也能正确转向，不依赖调用方。
2. `ENG.updateUnit` 统一递减 `hurtT` / `turnToSourceT`。
3. 敌人分支开头新增：受击时 `faceTowards(弹源, 13 rad/s)` + `alert=1` + 更新 `lastKnown`；
   若看不见目标则转 `hunt` 循弹源追过去。
   **关键：用 `reactedHitStamp !== hurtStamp` 做一次性标记** ——
   否则 900ms 窗口内每帧都清空路径，敌人会原地不动。
4. `js/player.js` 移除重复的 `hurtT` 递减（保持玩家行为不变）。

### 验证（_tools/hitreaction.js，20 项全通过）
- 背对玩家 180° 的敌人，1 秒内不会自己转过去（前提成立）
- 被击中后 0.5 秒内朝向偏离从 3.14 rad 降到 0.00
- 转向后重新发现玩家 → 进入 engage → **实际打出 18 发**（真的还手了）
- 看不见射手时从 idle → hunt，lastKnown 指向弹源
- hurtT 1 秒后归零（不再永久发白）
- 已在交战的敌人不会被踢回 hunt
- 玩家受击转向未被破坏

### 平衡影响（按上次教训换种子验证）
3 组种子合计 **35/36**（改前 33/36）—— 敌人会还手**没有**让游戏变难。
推测原因：敌人转身后主动靠过来，反而更容易在开阔处被清掉。
无论如何，没有回归。

### 测试脚本的小坑
- `hitreaction.js` 里找测试位置时，只放行了 `MAPGEN.T.FLOOR`（=1，室内）——
  但玩家现在生成在**建筑外**，室外格是 `EMPTY`（=0），导致一个位置都找不到。
  **写地图相关的测试时，FLOOR 和 EMPTY 都要放行。**
- 第 4 项测试一开始失败：我给的弹源方向让敌人转身后**恰好把玩家扫进视野锥边缘**（±45°），
  于是走了 engage 而不是 hunt。把弹源放到"继续背离玩家"的一侧才是干净的隔离场景。

## 第四轮：细分规划系统 + 切角

### 需求
「细分规划系统，设置路径节点可设置队员角度，以及切角（Shift+RMB，可搜索 DoorKicker2 切角实现方式以及效果）」

### 调研结论（DK2 实测说法）
- **Slice the Pie（切角）** = Shift + 右键拖拽（紫色箭头）："沿路径行走的同时持续转向，
  始终对准箭头所指的那个点"。绕门窗/拐角画弧线走位时最有用。
- **Strafe（固定角度）** = Ctrl + 右键拖拽（蓝色箭头）："边走边保持某个固定角度"。
- **Cancel point（取消点）** = 双击移动线：取消切角/强制朝向等持续动作。
- 其他：Shift+左键=Halt，Ctrl+左键=与友军同速，双击移动线插入 Cancel 点。

**关键认识**：我原有的 `FACE.FOCUS`（注视某点）在移动时锥本来就会扫 —— 语义上**已经就是切角**；
`FACE.HARD`（固定角度）就是 Strafe。所以不用新造机制，缺的是**节点级设置 + 取消点 + 可视化**。

### 实现
1. `player.js`：切角改为**以路径头节点为准**（原来 `t.path.find(FOCUS)` 会提前很远就生效）；
   新增 `cancel` 节点处理 —— 解除朝向模式并清掉后续节点上的朝向标记。
2. `ui.js`：`waypointAt`（点节点选中）、`pathInsertPoint`（Alt+左键插点）、
   右键拖拽给选中节点设朝向、`Del` 删除、`[` `]` 微调 5°、`UI.syncWpBar`/`UI.wpAction`。
3. `index.html` + `css`：节点编辑条（切角/固定角度/取消点/清除/删除 + 快捷键提示）。
4. `render.js`：节点选中高亮；切角画紫色虚线 + **视野锥扫过的弧线**；取消点画 ✕。

### 🚨 挖出的真 bug（影响面比本次需求更大）
**队员卡住重寻路时只保留最后一个路径点上的动作标记**，中间节点上规划好的
破门 / 救人质 / 切角 / 取消点会被**静默丢掉**。
- 定位手法：写探针逐帧打印路径长度与节点标记变化，看到
  `路径点 2 -> 3 剩余节点=[无 | 无 | focus]` —— 取消标记在重寻路后消失。
- 修法：新增 `ENG.carryWaypointFlags(from, to)`；重寻路改为**优先到下一个节点并保留后面所有节点**，
  用 `EngMove.noteRepathProgress` 做看门狗 —— 连续几次靠不近才退回旧的"直奔终点"，避免死循环。
- **A/B 验证**（`DK2D_OLD_REPATH=1`）：新旧行为都是 **56/60**，对平衡中性。

### 顺带修的可用性问题
**路径线原来画在战争迷雾之前**，未探索区域里的规划路径被压暗到看不清 ——
而规划恰恰最需要看清路线。已把路径绘制挪到 `paintFog` 之后。

### 测试脚本踩的坑（三次都是我自己写错，不是代码问题）
1. `walkLine` 会移动队员，我却拿**移动后的位置**当起点算位移 → 恒为 0。
2. `t.path.every(...)` 对**空数组恒为 true** → 取消点那条断言是 vacuous 通过。
   改成"只走到刚过取消点为止，让后续节点还在路径上"。
3. 插入点落在**线段终点之前**，所以插到下标 0 不是 1；归一化位置还用了过期的段长。
4. 探针里把敌人全杀掉 → m01 是清剿关，敌人清零**立刻判定任务结束**，
   `SIM.step` 提前 return，队员根本不动。**写探针时别把敌人清空。**

## 第五轮：路径点系统完全对齐 DK2

### 调研结论（DK2 完整动作集）
- **三种朝向**：Basic（黄，临时）/ Strafe（Ctrl，浅蓝，硬设定角度）/ Focused（Shift，紫，持续锁定一个点）
- **右键菜单**：蹲/站、跑/走、删除路径（从此点起）、换主副武器、换弹、spycam、门（踹/开）
- **路径编辑**：双击路径线 = Cancel point；**Shift+左键点路径 = Halt**；**Ctrl+左键点路径 = Match speed**；
  **Shift+数字 = GO Code 自动触发**；**Shift+F = 全体静默**；**Shift+~ = 切换 停下射击/不停下**
- 关键：DK2 的 Halt 是"停到你手动放开"，配合 GO Code 自动触发 = 标准同步突入

### 本轮实现
1. **停顿（Halt）**：节点带 `halt`，到达即 `t.halted=true` 并停止推进路径；
   `SIM.executeGo` 释放（`t.halted=false`）。节点被消费，用 `t.haltAt` 保留可视化标记。
2. **同速（Match speed）**：`wp.matchSpeed` 时按 8m 内最慢的**正在移动**的队友速度走。
   ⚠️ 关键细节：只算"正在移动"的队友 —— 否则已经就位的队友（curSpeed=0）会让全队停住。
3. **节点级动作**：蹲/站、跑/走、换弹、换枪、静默、停下射击/不停下（三态循环：未设→开→关）。
   ⚠️ 执行顺序：**先换枪再换弹** —— 反过来的话 `swapWeapon` 会把 `reloading` 清掉。
4. **冲刺噪音 + 静默**：冲刺每 0.55s 发出一次噪音（静默 2.5m / 正常 7m），静默同时把破门噪音 ×0.6。
   噪音 type 用 `'step'`，**不在行刑者的处决触发条件里**（shot/kick/breach/glass/boom），所以跑动不会害死人质。
5. **GO Code 自动触发**：`sim.goAuto/goArmed/goFired`。有人移动→武装；全组到位→触发一次。
6. **删除此点之后**：`path.splice(i)`。
7. **渲染**：节点动作图标横向排开（原来 6 种徽章全叠在同一点上）；停顿标记单独画。

### 🚨 差点又改错平衡（重要）
把 `t.autoShoot` 默认设成 DK2 的"停下射击"后，realplay 从 35/36 掉到 31/36。
加了 `DK2D_FORCE_AUTOSHOOT` 开关做 A/B（5 组种子）：
- 停下射击（DK2 默认）：10/10/11/11/11 = **53/60**
- 边走边打（本作原平衡）：12/11/11/11/11 = **56/60**
